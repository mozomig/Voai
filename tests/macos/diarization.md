# Разделение русской речи по спикерам

Замеры выполнены 20 ноября 2026 года на Apple M4 Pro с 24 ГиБ объединённой памяти, macOS 26.5.2, arm64. Взяты три монофонических микса из Veche Bench, ревизия `a0ab08d6887b64995d076b475a87310953a51138`, лицензия CC BY 4.0. Добровольцы записывали реплики сценария на русском языке. Авторы корпуса свели их в разговоры с разной длительностью пауз и наложений и предоставили время, текст и спикера каждой реплики. Два микса с тремя спикерами используют один диалог. Точность на спонтанной речи в одной комнате требует отдельной проверки с ручной разметкой такой встречи. [Карточка Veche Bench](https://huggingface.co/datasets/artem-tish/veche-bench)

## Установка и работа без сети

Рекомендуемый комплект занимает 31 137 485 байт. В нём INT8-конверсия pyannote Segmentation 3.0 (MIT, © CNRS, 2022) и голосовая модель 3D-Speaker CAM++ VoxCeleb (Apache 2.0). Ревизии, размеры и SHA-256 обоих файлов закреплены в `src/app/diarization.rs`. Статический runtime sherpa-onnx 2.0.2 (Apache 2.0) входит в подписанный исполняемый файл. При сборке приложения скрипт сверяет SHA-256 нативного архива для arm64. Вместо скачивания пользователь может выбрать свою папку с совместимой парой `segmentation.onnx` и `embedding.onnx`. Перед подключением приложение запускает обе сети на сгенерированном сигнале в отдельном процессе. [Релиз sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx/releases/tag/v2.0.2) · [Конверсия сегментации](https://huggingface.co/csukuangfj/sherpa-onnx-pyannote-segmentation-3-0) · [Лицензия исходной модели](https://huggingface.co/pyannote/segmentation-3.0) · [CAM++](https://modelscope.cn/models/iic/speech_campplus_sv_en_voxceleb_16k)

В чистом временном профиле штатная функция загрузила оба файла с Hugging Face, проверила хеши и открыла установленную пару. Повторный вызов с запретом всего сетевого трафика в macOS sandbox нашёл веса на диске и успешно проверил модели. Перестановка файлов сегментации и голоса привела к отказу в подключении. Отмена до начала загрузки оставила папку пустой. Подписанный `Voai.app` под тем же запретом сети выдал две порции результата на файле длительностью 76 секунд.

## Сравнение кандидатов

Первичное сравнение использовало первые 75 секунд каждого микса. DER включает пропущенную речь, ложное обнаружение и длительность речи с неверной меткой. Шаг измерения 10 мс, соответствие меток эталону выбрано оптимально один к одному. В оценку входят перебивания и границы реплик без допуска по времени. Для двух вариантов sherpa использован один поток CPU, сдвиг окна сегментации 0,20 и порог кластеризации 0,50. Для Nemotron использована реализация Transformers на четырёх потоках CPU.

| Микс | Sherpa + CAM++ · DER / меток | Sherpa + WeSpeaker ResNet34-LM · DER / меток | NVIDIA Nemotron-3 · DER / меток |
| --- | --- | --- | --- |
| Двое | 13,99% / 2 | 14,94% / 2 | 8,77% / 2 |
| Трое | 26,15% / 5 | 37,99% / 2 | 7,75% / 3 |
| Трое с перебиваниями | 14,86% / 4 | 37,92% / 2 | 7,21% / 3 |

На этих фрагментах sherpa с CAM++ через Python обрабатывала 75 секунд за 2,77–2,86 с, пик процесса составлял 140–190 МиБ. WeSpeaker потребовалось 5,23–6,04 с и 137–179 МиБ. Nemotron в том же процессе обработал первый фрагмент за 2,12 с, два следующих — за 0,53–0,59 с. Пик процесса составил 691–733 МиБ, файл весов занимает 378,6 МиБ, лицензия OpenMDW 1.1. Число потоков и степень прогрева различались. Nemotron допустил меньше ошибок на всех трёх фрагментах. Для поставки выбран CAM++ благодаря размеру комплекта и доступному нативному runtime для macOS. Официальные веса Pyannote Community-1 требовали авторизованного доступа через Hugging Face. Они используют формат PyTorch, который текущий ONNX-обработчик не загружает. [NVIDIA Nemotron-3-Diarization](https://huggingface.co/nvidia/Nemotron-3-Diarization/tree/52a432672732425e4c19765b9fec9b5810e6f4ba) · [Условия доступа и запуск Community-1](https://huggingface.co/pyannote/speaker-diarization-community-1)

## Точность на распознанных словах

На первых трёх фрагментах подобран порог кластеризации 0,75. Следующие 75 секунд каждой записи отложены для проверки. Оба набора фрагментов обрабатывались нативной реализацией, со словами и таймкодами от Whisper Small на русском языке. SHA-256 использованного файла GGML — `1be3a9b2063867b937e64e2ec7483364a79917e157fa98c5d94b5c1fffea987b`.

Тест последовательно сопоставляет совпавшие слова Whisper со словами эталона. Если совпадение отстоит от соответствующей реплики более чем на 1,5 с, оно исключается. Как и в интерфейсе, слово относится к голосу с наибольшим пересечением по времени. В таблице отдельно показаны ошибки и слова, которым система не присвоила спикера. Даже при правильном числе спикеров система может принять одного участника за другого. В контрольном разговоре на троих это произошло с 32 из 123 совпавших слов. В редакторе можно переназначить спикера реплики и прослушать спорный участок.

## Потоковая обработка и расход памяти

Rust-обработчик читает PCM окнами по 75 секунд и добавляет до пяти секунд контекста с каждой стороны. Он отдаёт интервалы центральной части в JSONL и освобождает звуковые данные этого окна. CAM++ извлекает нормированный вектор голоса из непересекающихся с другими спикерами участков общей длительностью до 12 секунд на человека. Для сопоставления между окнами используются косинусное сходство голосов и общие речевые интервалы на стыке. В памяти остаются последний стык и максимум 256 голосовых профилей. При превышении этого числа дольше всего отсутствовавший голос вытесняется и при возвращении может получить новую метку.

Проверочная запись содержит двух участников A и B. На отметке 75,0 с вступает третий участник C, позже A произносит другие фразы. Между голосовыми участками вставлена тишина. Для каждого прогона запущен новый нативный процесс, пиковый RSS снят через `/usr/bin/time -l`. Во всех случаях последовательность ID была 0, 1, 2, 0.

| A возвращается через | Пик RSS | Время с учётом конкурирующих сборок |
| --- | ---: | ---: |
| 150 с | 125,8 МиБ | 57,23 с |
| 30 мин | 137,2 МиБ | 79,85 с |
| 90 мин | 137,4 МиБ | 51,37 с |

Полностью нулевые окна пропускаются. Таблица измеряет устойчивость меток, смещения времени и память обработчика при увеличении длительности. Память Whisper, AVFoundation, интерфейса и место на диске для декодированного PCM учитываются отдельно.

В дополнительной проверке один и тот же микс из трёх голосов с перебиваниями повторялся без длинных пауз. Это задействует обе сети и сопоставление голосов в каждом окне. При увеличении записи с 3 мин 45 с до 11 мин 15 с пиковый RSS вырос на 2,5 МиБ. Во всех трёх случаях сохранены три глобальные метки.

## Как повторить

Из корня репозитория укажите приложение, папку с двумя ONNX-моделями, файл Whisper и каталог для Veche Bench. При первом запуске флаг загрузки разрешает получить публичные WAV и CSV авторов. В последующих запусках можно использовать локальную копию без обращения к сети. Скрипт выводит только численные результаты.

```sh
python3 tests/macos/diarization.py target/dist/release/Voai.app \
  /path/to/onnx-pair /path/to/ggml-small.bin target/qa/interviews \
  --download-fixtures --stream-check
```
